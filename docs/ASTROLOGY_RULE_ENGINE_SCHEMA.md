# โครงสร้างข้อมูลและกติกาเรียกใช้ความรู้โหราศาสตร์

สถานะ: **DISCOVERY** — เป็นสัญญาข้อมูลและแบบร่างสำหรับต่อยอด ยังไม่ใช่การเปิดใช้ผลทำนายในหน้าแอป

## เป้าหมาย

ให้ HORA แยกข้อมูลออกเป็น 3 ชั้นที่เชื่อมกันได้:
1. **Chart facts** — ตำแหน่งดาว ราศี องศา และภพของผู้ใช้แต่ละคน ซึ่งมาจากเครื่องคำนวณดวงที่มีอยู่
2. **Rule data** — ตารางเงื่อนไขที่บอกว่าดาวในราศีใดตรงกับมาตรฐานใด ภายใต้ระบบ/สำนักใด
3. **Interpretation content** — คำอธิบายความหมาย ซึ่งเรียกใช้หลังจากรู้ข้อมูลดวงและกฎแล้ว ไม่ควรปะปนกับการคำนวณ

## โครงสร้างไฟล์

- `data/astrology/planetary_dignities.json` — กฎแบบเครื่องอ่านได้สำหรับค้นมาตรฐานดาวตามดาวและราศี
- `js/data/thai-special-criteria.js` — คลังเกณฑ์พิเศษโหราศาสตร์ไทย (รูปแบบดวง/องค์เกณฑ์/โยค) พร้อมดาว เงื่อนไข และสถานะตรวจสอบ; ยังเป็น reference-only
- `docs/THAI_SPECIAL_ASTROLOGY_CRITERIA.md` — ตารางสรุปสูตรที่พบและรายการที่รออาจารย์แทนยืนยัน
- `qa/formula-tests/thai-special-criteria.test.js` — ทดสอบความครบของ metadata และป้องกันไม่ให้สูตรที่ยังไม่ยืนยันถูกเปิดใช้
- `docs/THAI_ASTROLOGY_KNOWLEDGE_BASE.md` — คำอธิบายแนวคิด ขอบเขต และสถานะ
- `docs/ASTROLOGICAL_STANDARDS.md` และภาคผนวก — รายละเอียดเกณฑ์และข้อควรระวัง
- มีฟังก์ชัน lookup แล้วที่ `js/astrology/knowledge.js` และชุดทดสอบที่ `qa/formula-tests/astrology-knowledge.test.js`; ต้องรัน CI ให้ผ่านก่อนเชื่อมกับ UI

## สัญญาข้อมูลขั้นต่ำ

```json
{
  "chart_id": "user-chart-identifier",
  "planet": "mars",
  "sign": "aries",
  "longitude": {"degrees": 12, "minutes": 30},
  "house": 4,
  "zodiac_system": "must-be-explicit",
  "house_system": "must-be-explicit"
}
```

ตัวอย่างนี้เป็นเพียงรูปแบบข้อมูล ไม่ใช่ข้อมูลผู้ใช้จริง

กฎหนึ่งรายการควรมี `rule_id`, `system_id`, `category`, เงื่อนไข, `status`, `version`, หมายเหตุที่มาของข้อมูล และกรณีทดสอบที่คาดหวัง ข้อมูลจริงในไฟล์ JSON ฉบับแรกจัดกลุ่มตาม `category` เพื่อให้เห็นการจับคู่ได้ง่าย; แต่ละคู่ดาว-ราศีถูกจัดเป็น record ที่มี `rule_id` ใน `data/astrology/planetary_dignities.json` และมีชุดทดสอบ lookup เบื้องต้นแล้ว

## ขั้นตอนการเรียกใช้

1. อ่านผลดวงของผู้ใช้ที่คำนวณแล้ว โดยใช้ราศีและภพจากผังของผู้ใช้นั้นเอง
2. รับ `system_id` ที่เลือกชัดเจน
3. ค้นทุกกฎที่ตรงกับ `planet + sign + system_id`
4. รวมป้ายมาตรฐานที่ตรงทุกข้อ ไม่ทิ้งกรณีซ้อนกัน
5. ผนวก `house` จากข้อมูลดวงเดิมเพื่อแสดง “ดาว — ราศี — ภพ — มาตรฐาน”
6. แสดงสถานะกฎและคำเตือน ถ้าสถานะยังเป็น DISCOVERY/CALIBRATING
7. เก็บ rule IDs ที่ใช้ เพื่อให้ตรวจสอบผลย้อนหลังได้

## ตัวอย่างที่ต้องรองรับ

- ผู้ใช้ A: อังคารอยู่เมษ ภพ 4 → ค้นป้ายมาตรฐานจากกฎของอังคารในเมษ และแสดงภพ 4 จาก chart facts
- ผู้ใช้ B: อังคารอยู่เมษ ภพ 10 → ใช้กฎดาว/ราศีชุดเดียวกัน แต่แสดงภพ 10 จาก chart facts ของผู้ใช้ B
- ถ้าสองสำนักให้ผลไม่เหมือนกัน → แสดงแยกตาม system_id ห้ามรวมตารางเงียบ ๆ
- ถ้ามีกฎหลายประเภทตรงกัน → ส่งคืนทุกประเภทพร้อมสถานะ ไม่เลือกทิ้งเอง
- ถ้าไม่พบกฎ → ตอบ “ไม่มีข้อมูลกฎในชุดที่เลือก” ไม่เดาค่า

## ข้อห้าม

- ห้ามใช้ตารางมาตรฐานเพื่อปรับแก้สูตรคำนวณตำแหน่งดาวหรือลัคนา
- ห้ามคำนวณภพจากราศีเพียงอย่างเดียว
- ห้ามนำข้อมูลจากผู้ใช้หนึ่งไปใช้เป็นภพของผู้ใช้อื่น
- ห้ามยกระดับกฎ DISCOVERY เป็น GOLDEN/LOCKED จนกว่าจะมีแหล่งมาตรฐานที่ตกลงกันและชุดทดสอบผ่าน
- `js/astrology/knowledge.js` เป็นชั้น lookup แยกจากเครื่องคำนวณ; ยังไม่ผูกเข้ากับ `index3.html` หรือ UI จนกว่า CI และตัวอย่างผลจริงจะผ่านการตรวจสอบ
